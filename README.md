# KRS Radar

Закритий дашборд над базою `Companies_KRS_dataset.xlsx` (SharePoint): нові польські компанії з українськими власниками.

**Сайт:** https://wh1m1337.github.io/krs-radar/ — доступ лише за логіном і паролем.

## Як це влаштовано

- `index.html`, `app.js`, `style.css` — статична сторінка на GitHub Pages. У репозиторії немає ні даних, ні ключів.
- `supabase/functions/krs-api` — серверна функція в окремому проєкті Supabase `krs-dashboard`: логін (PBKDF2, сесії 7 днів, блокування після 5 невдалих спроб), адміністрування акаунтів, видача даних, імпорт xlsx.
- Таблиці (`krs_companies`, `krs_work`, `krs_touches`, `krs_contacts`, `krs_sync_log`, `dash_users`, `dash_sessions`, `dash_settings`) закриті RLS — читати й писати може лише функція.
- `sync/krs-sync.sh` — щогодинна синхронізація: Chrome забирає файл зі SharePoint, скрипт відправляє його з ключем із `~/.config/krs-radar/ingest_key`.

## Акаунти

Перший вхід: `Admin` / `Admin` — система одразу вимагає змінити пароль. Адміністратор додає колег у вкладці «Адміністрування»; нові акаунти теж змінюють тимчасовий пароль при першому вході.

## Відповідність (0–100)

Єдина оцінка дашборда. Рахується лише з полів бази; розклад видно в картці компанії. Рівні: Висока ≥60, Середня 40–59, Низька <40.

| Складова | Бали |
|---|---|
| Фізичний об'єкт: підтверджений у тексті (склад, цех, магазин, офіс, автопарк…) / галузь, що без об'єкта не працює (за PKD) | 30 / 15 |
| Цільові галузі: виробництво, логістика, фінанси, медицина, рітейл, держсектор — 25; проф. послуги, енергетика — 12; медіа, HoReCa, освіта — 10; будівництво, клінінг/кадри, нерухомість — 6; IT — 0 | до 25 |
| Вікно запуску: реєстрація ≤30 дн. / ≤90 дн. | 20 / 10 |
| Масштаб: підтверджена виручка (8), команда/вакансії (5), капітал ≥100 тис. (5) або ≥50 тис. (3) | до 15 |
| Контакт: відомий ЛПР, підтверджений сайт | 5 + 5 |

Фрази «не підтверджено», «заявлено…», «головний профіль…», «гіпотеза» доказом не вважаються. IT-компанії позначені «партнер/конкурент» і не потрапляють у «Найперспективніші». Мітка відповідності з Excel в оцінку не входить — вона показується в картці як «Оцінка дослідника» поруч з обґрунтуванням.

## Робота з компанією

- **Картка компанії:** статус, відповідальний, пріоритет (A / B / C / партнер), сегмент, ICP, місяць циклу, посилання на підтвердження, блокер.
- **Контакти (ЛПР):** прив'язані до компанії; посада, LinkedIn, email, телефон, мова, джерело, стан запрошення, позначка «релевантний ЛПР».
- **Дотики:** канал, контакт зі списку, результат, наступний крок і позначки «змістовний», «теплий», «Discovery», «кваліфіковано». Нотатка ніколи не рахується змістовним дотиком.

## Зарахування

Компанія зараховується автоматично, коли виконано всі сім умов: ICP = Так; щонайменше 2 релевантні ЛПР; 3 змістовні дотики; 2 різні канали; зафіксований результат дотику; наступна дія з датою (або компанію закрито: «Не релевантно» / «Передано в CRM»); є підтвердження. Дату зарахування ставить сервер у момент, коли умови виконались; якщо умова перестає виконуватись, позначку знято.

## Цикл

Вкладка «Цикл»: межі циклу, цілі, план на людину (компаній на місяць), показники за поточний і попередній тиждень, поточний місяць і весь цикл, частка каналів, воронка й якість даних по компаніях «у плані» (з позначкою «Місяць циклу»). Межі, цілі й план змінює адміністратор там же.
